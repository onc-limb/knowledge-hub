すべてを AI Agent に実装させたことはあるだろうか。

筆者はある。
個人用の家計管理ダッシュボードを作っていて、機能を細かいタスクに分割し、複数の Agent に並列で書かせていた。
たとえば「金額の計算ロジック」と「画面表示」を、別々の Agent に同時に書かせる、という具合だ。
各タスクの受け入れ条件は「型チェックとテストが通ること」。それだけ。

で、上がってきたコードを合わせて動かしたら、画面の数字が全部 0 だった。
ランタイムエラーは出ない。表示だけが静かにズレている。

原因はこれ。

```typescript
const data = summary as unknown as Record<string, unknown>;
const amount = (data.dividendAmount ?? data.dividend ?? 0) as number;
```

画面表示を担当した Agent は、呼び出し先の計算ロジックがまだ無かった。
そこで引数の型を仮置きし、何が来ても受け取れるように `as unknown as` でつじつまを合わせていた。
フィールド名が実際とズレていても、キャストと `?? 0` が全部飲み込む。
だから型チェックは通り、実行も正常終了し、値だけが 0 になる。

## 思ったこと

**自分で書いていたら絶対にしないもみ消しを、Agent は平然とやってくる。**
「型チェックを通せ」と言われたら、通すための最短経路を選ぶ。
`as unknown as` はまさにその最短経路で、`tsc` は `strict: true` でもキャストを疑わない。
なので、リントで明示的に禁止しておくべきだった。
typescript-eslint の `consistent-type-assertions` を `assertionStyle: "never"` にすると、この手のキャストは全部エラーになる（上のコードで 5 件検出された）。

**タスクを細かく切れば並列で早い。ただ、タスクごとの受け入れ条件が厳しすぎると、Agent は無理やり回避する。**
呼び出し先がまだ存在しないタスクに「型チェックが通ること」を課せば、キャストで逃げるしかない。
単体では型エラーが出ていて構わないタスクと、全体として動くことを確認するタスクは分けて、粒度に合った合格条件を置くべきだった。

そもそも型をちょろまかすなら JavaScript でいいわけで、なんで TypeScript 使ってるのか考えてよ……とは思う。
ただ、最近の AI が進歩しすぎて忘れがちだったけど、AI はやっぱり機械なんだな〜と。
人間なら「型チェックを通せ」と言われても、それより優先すべき暗黙のルール（キャストで逃げない）を自然と見極める。
AI は言われたことを何よりも優先して、型チェックを通してくる。

だから、TypeScript の型を信じるには、その暗黙のルールを明示的に定義し直す必要がありそうだ。
逆に言えば、AI はコードを書くこと自体は得意なので、人間相手なら窮屈だったルールも、今まで以上に厳しくしてしまっていい。
まずは `as` の禁止から始めていきたい。
